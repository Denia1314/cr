# Royal Lab 皇室战争离线人机训练控制台

这是一个面向 **MuMu 模拟器离线/人机 1v1** 的 Windows 桌面控制台。它通过 ADB 截图与点击运行，不修改游戏进程、不读写游戏内存，也不包含天梯匹配、反检测或绕过限制的功能。

## 打开桌面 UI

直接双击：

```text
启动控制台.vbs
```

启动时不会显示命令行黑框。也可以双击 `start_ui.bat`，它会调用 `pythonw` 打开相同界面。

桌面控制台提供：

- MuMu、ADB、游戏包和分辨率状态检测
- 实时模拟器画面预览
- 试运行/正式运行切换
- 单次训练局数设置，`0` 表示持续运行
- 开始训练与安全停止
- 全局识别并点击蓝色“确定”按钮与可领取奖励宝箱
- 实时彩色运行日志
- 离线安全门和本次完成局数状态
- 画面标定入口和训练数据目录入口
- 连续对局数据采集和人工标注入口

## 双机 / 团队训练数据共享

自动对战回放支持通过独立私有仓库同步。新电脑运行 `setup_sync.bat` 后重启控制台；左侧“双机数据同步”可立即同步，控制台打开期间每 60 秒自动同步。指定训练机汇总经验训练并发布通过验证的回放策略模型，其他电脑负责采集和接收。原有模型验证与实战启用门槛保留。

成员需要同时加入代码和数据仓库。详细接入、权限、训练和断网行为见 [双机训练共享说明](docs/training-sharing.md)。

## 第一次使用

1. 打开桌面控制台，点击右上角“连接并检测”。
2. 确认 MuMu 已安装皇室战争，并进入离线/人机 1v1 页面。程序会自动识别 MuMu 安装路径。
3. 点击左侧“画面标定”，在 MuMu 画面中框选能明确证明当前是离线人机模式的稳定文字或图标，然后保存。
4. 回到控制台，保持“试运行”开启，点击“开始训练”检查识别结果。试运行只截图和记录，不会点击。
5. 确认识别稳定后关闭“试运行”，设置局数并开始正式训练。

### 按 ADB 端口自定义连接

如果使用 MuMu 多开或其他本地模拟器，可以不用 MuMu CLI 自动发现：

1. 先启动模拟器，并确认它已开启 ADB 调试。
2. 在控制台右上角点击“自定义 ADB”。
3. 输入模拟器显示的 ADB 端口（例如 `7555`），点击“保存并连接”。

程序会保存该端口，并直接连接 `127.0.0.1:<端口>`。后续的环境检测、截图、标定、自动训练和示范学习都会使用这个连接。如需切回原来的 MuMu 自动发现，再次打开该窗口并点击“恢复自动发现”。

程序会优先使用 MuMu 目录、Android SDK 或 `PATH` 中的 `adb.exe`。如果模拟器使用独立 ADB，也可在 `config.json` 的 `mumu` 中增加 `"adb_path": "ADB 程序的完整路径"`。

## UI 状态说明

- **模拟器**：显示 ADB 是否连接、设备序列号与当前截图分辨率。
- **安全门**：模板已标定只代表配置就绪；每次运行仍需连续 3 帧识别到离线标志才允许点击开始。
- **已完成**：显示本次启动后已经完成的对局数。
- **设备画面**：运行时自动刷新，也可以手动点击“刷新”。
- **安全停止**：通知引擎在当前设备操作结束后退出，不会继续执行下一次点击。

## 训练数据

点击左侧“训练数据”可直接打开目录：

```text
runs/<日期时间>/
  dataset.json
  events.jsonl
  frames/*.jpg
  samples.jsonl
  samples/*.jpg
  annotations.jsonl
```

`events.jsonl` 和 `frames` 用于审计机器人运行过程。`samples.jsonl` 与 `samples` 是按固定间隔采集的连续战斗画面，初始状态始终是 `unlabeled`；机器人自己的出牌不会被当成正确答案。

为避免训练数据无限占用磁盘，默认每 2 秒保存一张最长边 960 像素、质量 65 的战斗画面；`battle_action` 只写事件日志，不再重复保存截图。每次启动最多写入 200 MB 图片，达到上限后仍会继续运行并记录 JSON 日志。以上参数可在 `config.json` 的 `dataset` 中调整。

结算后会优先识别并点击蓝色“确定”按钮；进入宝箱或奖励全屏界面后，会点击界面中央推进奖励动画，直到重新识别到离线大厅。

安全停止训练后，点击左侧“数据标注”即可：

- 填写当前四张手牌的稳定 `card_id`
- 左键拖框标出敌我单位及其归属
- 标记防守、中立或推进阶段
- 排除加载画面、遮挡严重等不可用样本

人工结果追加保存在 `annotations.jsonl`，每次修改会增加版本号并保留历史记录。也可以双击 `annotate.bat` 单独打开标注工具。

## 全卡牌知识库

`data/cards.json` 是与当前卡组无关的版本化卡牌知识库。当前已建立 120 张社区静态卡牌资料、120 张基础卡图和 59 张进化/英雄卡图。运行时会把画面中的四个手牌槽与整个目录匹配，不会根据某一套卡组写死编号。

无官方 token 时，可重新建立目录并补齐本地卡图：

```text
python -m crbot --config config.json cards-sync --community-bootstrap
```

社区目录用于离线识别引导，可能晚于游戏版本；识别分数不够时卡牌保持 `unknown`，策略会等待而不是猜一张牌。资料来源为 RoyaleAPI 的公开静态数据和卡图仓库。若目录落后，应优先用下面的官方接口同步基础字段，再人工核对战术字段。

取得 Clash Royale 官方 API token 后，可同步全部卡牌的官方 ID、英文名、费用、稀有度、等级字段和图标地址：

```text
set CLASH_ROYALE_API_TOKEN=你的Token
python -m crbot --config config.json cards-sync
```

也可以导入已经保存的官方 `/v1/cards` JSON：

```text
python -m crbot --config config.json cards-sync --input official_cards.json
```

再次同步会保留人工填写的中文名、类型、目标、战术角色、克制关系和配合关系。官方基础资料不等于战术知识，后续仍需逐项核对这些人工字段。

## 当前运行策略

1. 连续识别已标定的离线人机标志。
2. 自动点击固定的黄色对战按钮。
3. 通过底部圣水 UI 判断是否进入战斗。
4. 根据圣水与左右路画面活动量选择防守或推进位置。
5. 自动判断战斗结束并点击确定；返回大厅和主大厅阶段不检测、不点击奖励宝箱进度条。
6. 返回大厅并重新验证离线标志。

默认启用 `reactive_catalog` 通用响应策略：

1. 在四个手牌槽中识别基础、进化和英雄卡面，读取该牌费用、类型和战术角色。
2. 从对方部署区开始追踪红色等级标记，并比较前后帧的位置，判断左右路压力、接近程度和向我方移动速度，不再等到敌军进入塔下。
3. 群体威胁优先范围伤害或法术，重压优先高伤、建筑或人海，普通单体优先低费牵制。
4. 没有威胁时从 6 费开始主动组织推进。策略从全卡牌目录中的角色、费用和说明文字推导前排、后排、混合、建筑与法术画像：先组成前排，再把屠夫、火枪手、法师等后排放到其身后；坦克沉底、快速胜利条件贴桥，手里暂时没有合适前排时不会把纯后排当肉盾乱扔。
5. 不出费用不足的牌；手牌未知或没有合理候选时等待，不再随机轮换卡槽。
6. 防守落点依据敌军最前位置、移动速度和我方卡牌类型实时计算：法术瞄准敌群中心、建筑居中拉扯、近战前置拦截、远程在后方输出。防守牌可以直接解场；威胁解除后会短时记住该路存活的阵型，若存活的是屠夫等后排，就在其前方补前排，若存活的是前排，则在其后补输出并同路反打。

通用策略会根据对方单位数量、位置和压路程度响应，并可叠加下方无需框选的手动示范模型。逐个识别敌方精确卡名的检测器是可选增强，不是运行或示范学习的前置条件。

如需恢复最初的活动量/随机卡槽基线，把 `config.json` 中的 `policy.mode` 改为 `baseline`。`reactive_catalog` 下的 `fallback_mode` 默认为 `hold`，感知模块缺失时不会盲目下牌。

## 自我学习与模型升级

### 直接学习你的手动操作

如果不想逐帧框选，进入已标定的离线人机入口后，点击桌面控制台左侧“示范学习”，然后像平时一样手动对战即可。程序通过 MuMu 的只读触摸事件流监控你的操作，不会替你点击：

- 菜单、主页面和未通过离线安全门的触摸全部忽略。
- 战斗中的所有原始触摸都会保存；选牌后落牌或直接拖牌会合并成一条专家动作。
- 每条动作保存操作前后画面、四张手牌、圣水、左右路压力、所选卡槽和归一化落点。
- 人的卡槽选择与落点标记为真值；机器识别出的卡名和威胁状态明确标记为观察值，不会冒充人工标签。
- 选中或拖动造成卡槽暂时变空时，会利用同局前一时刻的稳定手牌自动复原，不需要手工补标签。
- 模仿模型学习战场画面边缘、费用、卡牌类型/角色和路压特征，不把卡牌 ID 作为输入，因此不会只背住当前卡组。

也可以双击 `demonstrate.bat` 启动。累计达到 100 次有效出牌、10 局对战和至少 12 种使用过的卡牌后，停止示范录制时会自动训练。训练使用逐局留出交叉验证：达到完整标准时全权重融合；只达到可靠辅助标准时以降低后的权重融合；两种标准都不达标则不启用。

可以随时查看示范学习进度：

桌面控制台左侧“无标注自学”会直接显示这套模型的状态；有新增且达到门槛的示范数据时，会自动训练并只晋级验证合格的候选模型。也可以使用命令行：

```text
python -m crbot --config config.json imitate audit
```

通过验证的模型会在下次自动训练启动时与现有规则策略融合：规则继续负责费用、未知牌、对手压力和非法落点等硬约束，模仿模型影响符合安全条件的选牌偏好与落点。原始记录位于 `demonstrations`，模型位于 `models/imitation`。这条路线不需要打开人工框选工具。

### 自动战斗奖励与经验回放

自动战斗现在也会无标注地记录完整的强化学习经验：每次实际下牌保存“当前状态—动作—下一状态”，结算页出现后再自动统计顶部红方与底部蓝方的皇冠，并给整局补上胜、负或平局回报。

- 只有同时识别到结算确认按钮、六个皇冠槽都稳定且置信度达标时，奖励才标为可信。
- 结算仍在动画、画面不完整或识别含糊时，本局奖励记为不确定，不进入训练。
- `--dry-run` 的假动作不会写进经验回放。
- 机器人自己的动作不是专家真值。默认 `allow_bot_training=false`；允许离线生成影子候选，但不允许候选接管实战，避免用失败策略反复训练自己。
- 每局的回放保存在对应 `runs` 目录内的 `replay_transitions.jsonl` 和 `replay_episodes.jsonl`。
- 新记录会额外保存左右路各自的威胁类型、接近程度、推进速度、单位数、阵型阶段和对局时间，用于区分提前防守、直接解场、前排、后排和反打。
- 每次点击都有唯一 `action_id`。点击后的连续画面必须同时提供至少两项独立证据（稳定换牌、圣水扣减、卡槽变化）才记为 `confirmed`；`rejected` / `unknown` 尝试会保留在回放，但不会进入开启确认门槛的新模型训练。

### M2：稳定感知与响应速度

当前规则版本为 `adaptive_counterpush_v5_m2`。M2 在不依赖固定卡组的前提下补上了运行时闭环：

- 四个手牌槽保留短时历史、置信度和新鲜度；单帧遮挡不会立刻换牌，已确认使用的槽位会阻止陈旧截图再次出牌，直到看到替换牌。
- 圣水视觉读数按置信度融合到虚拟圣水；视觉暂时不可用时保守回退到计时，并在双倍圣水阶段按阶段速率分段计时。
- 前排/后排阵型记忆随时间和置信度衰减；没有新的己方观测时不会永久假定单位仍然存活。
- 敌军相邻帧匹配限制为一对一，接近速度除以真实帧间隔，避免截图变慢造成异常加速；高压威胁才会使用更短的紧急冷却。
- 运行事件记录 `screenshot`、`perception`、`decision`、`send`、`confirmation` 和总响应耗时，按样本提供 P50/P95 诊断；动作回放同时保存手牌/圣水时效字段。

M2 不会把旧回放改写成新版本数据。新的确认动作应在新版本运行中积累，达到门槛后再按 M1 的冻结评估协议训练；旧版本经验仅作为显式迁移来源。

查看现有经验量：

```text
python -m crbot --config config.json replay audit
```

对尚未生成回放的旧对局做一次安全回填：

```text
python -m crbot --config config.json replay backfill
```

生成一次影子候选并做离线验证：

```text
python -m crbot --config config.json replay train
```

只读查看当前快照、冻结评估集和冠军状态（不会改冠军、注册候选、同步或上传）：

```text
python -m crbot --config config.json replay evaluate
```

训练只使用 `training_policy_version` 指定的同版本、已确认动作。除了随机的完整对局隔离验证，还会强制使用最新 25% 对局做时间外推验证，并按固定哈希预留冻结评估集，以阻止只会拟合旧数据、到了新对局就退化的候选晋升。检查指标包括胜负平衡准确率、AUC、概率误差、相对随机基线的选牌排序提升和胜局落点误差。当前的第一阶段门槛是至少 50 局可信结算、10 胜、10 负和 300 条已确认动作。达到数据量门槛只表示可以训练影子候选；只有验证与排序门槛都通过且显式设置 `allow_bot_training=true` 时，候选才有资格以 10% 的低权重晋升。

### 精确敌军识别模型

这是可选的精确卡名检测路线，与上面的无标注示范学习互不依赖；不想手动框选可以完全跳过本节。

桌面控制台左侧“精确标注（可选）”可打开框选工具；“无标注自学”的状态窗口会把这里单独列为可选增强。也可以双击 `learning.bat` 或运行：

```text
python -m crbot --config config.json learn audit
```

第一版战场检测模型必须先满足 `config.json` 中的种子数据门槛：200 张人工框选帧、300 个目标框、10 局对战和至少 12 种不同卡牌。机器人动作、手牌自动识别结果和模型自己的预测都不会冒充人工真值。

达到门槛后安装训练依赖并开始训练：

```text
python -m pip install -r requirements-training.txt
python -m crbot --config config.json learn train
```

训练集和验证集按整局对战切分，验证集只使用人工真值。候选模型必须同时达到精确率、召回率、mAP50 和 mAP50-95 门槛，并且综合分高于现有模型，才会登记为冠军模型；未达标模型保留审计记录但不会用于运行。

冠军模型存在后，可对尚未人工标注的画面生成高置信度伪标注：

```text
python -m crbot --config config.json learn auto-label --limit 500
```

完成第一次人工种子标注后，日常可以直接运行安全学习闭环：

```text
learning.bat cycle
```

它会先审计数据；未达门槛时只报告缺口，不会训练。已有冠军模型时会先生成最多 500 帧高置信度伪标注，再训练候选模型、用纯人工验证集评分，并根据晋级门槛决定是否替换冠军模型。

伪标注单独写入各运行目录的 `pseudo_annotations.jsonl`，不会覆盖 `annotations.jsonl`。只有当前冠军模型置信度不低于 0.94 的预测才可进入下一轮训练，伪标注帧数和目标框数都不能超过人工训练数据的 50%，且永远不能进入验证集。训练产物保存在 `models/battlefield`，数据导出保存在 `training/exports`。冠军模型会在下次启动时自动接入策略，提供对手精确卡名；模型缺失或推理失败时自动回到通用压路检测。

## 安全限制

- 仅允许 `game.allowed_mode = offline_ai_only`。
- 离线标志必须连续多帧识别成功，且在开始按钮点击前仍然有效。
- 非战斗画面会全局检查蓝色“确定”与已点亮的奖励宝箱；确定按钮优先。
- 启动时已经位于战斗中不会直接接管，因为无法证明该局属于离线人机。
- 前台离开游戏或未知页面持续超时后会自动停止。
- 不要把离线标志标定到排位赛、活动赛或任何真人匹配页面。

## 高级命令行入口

桌面 UI 已覆盖日常使用。只有调试时才需要以下脚本：

- `doctor.bat`：环境检查
- `calibrate.bat`：单独打开标定窗口
- `annotate.bat`：单独打开可选的精确敌军数据标注窗口
- `learning.bat`：检查可选精确识别模型的数据门槛
- `demonstrate.bat`：只读监控手动离线对局并学习选牌与落点
- `python -m crbot --config config.json replay audit`：检查自动胜负奖励与经验回放进度
- `python -m crbot --config config.json replay evaluate`：只读评估数据分层、冻结集与当前冠军
- `python -m crbot --config config.json replay train`：训练并验证回放影子候选
- `start_bot.bat --dry-run`：命令行试运行
- `start_bot.bat --max-battles 3`：命令行运行 3 局
- `run_tests.bat`：运行自动化测试

Python 依赖记录在 `requirements.txt`。`start_bot.bat`、`start_ui.bat` 和 `setup_sync.bat` 会先检查依赖，首次使用或 Python 环境更新后会自动安装缺少的包。
