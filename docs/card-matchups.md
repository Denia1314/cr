# 数据库兵种比较（3.10.14，G1）

预测策略的落点预筛选与战斗精算共同使用 `data/battle_knowledge.json`。
过去预筛选只取召唤列表中的第一个单位，主要比较攻击目标、距离、拉扯和塔火覆盖。
现在逐个比较全部召唤成员，以数量加权汇总位置评分；连续拦截候选也包含各成员的射程。

预筛选读取配置等级对应的血量、护盾、单次伤害、攻击间隔、首击时间、移动速度、
射程、部署时间、召唤数量、空地目标、只攻击建筑和范围伤害属性。
先估算需要几次攻击才能消灭当前敌人：护盾单独消耗命中次数，过量伤害不算作额外输出；
结合自身承伤存活时间提高有效拦截点的优先级。
单体攻击按多个召唤单位逐个承伤估算，范围攻击保守按成组承伤估算。
这会实际改变预筛选评分和有限预算内进入战斗精算的先后次序，不只是显示属性。

CPU 与 CUDA 使用相同的兵种比较特征。最终选牌、落点、等待与后续组合继续比较完整战斗分支，
包括塔损、敌方回应、费用和留费约束；本次局部对战估算不会覆盖这些结果。

每张手牌的 `hand_evaluations[].database_comparison` 记录数据库版本、来源、假设等级、
全部成员及数量、实际数值、未支持机制，以及对当前敌军的命中次数、击杀时间和存活时间估算。
法术记录执行参数。无法攻击的目标使用空击杀时间，不冒充有效输出。

这些比较属于近似预筛选：移动、群体站位、实际集火、范围覆盖和特殊机制依赖后续模拟；
敌军身份不确定时，记录可能对应推演假设，不能视为已识别的真实敌军。
数据库保留公开详情与历史机制混合来源，不表示当前平衡已核验。
本次不修改数据库平衡数值、模型权重、策略身份或兼容性，不宣称完成真实对局验收。
显式旧策略或感知不可用时的旧策略回退仍使用原来的规则；本次改动作用于预测策略。

验证覆盖护盾命中、过量伤害、攻速、数量、范围承伤、空地限制、属性对实际评分的影响、
混合召唤卡全部成员参与、CPU/CUDA 一致性，以及防守与组合推演回归。
