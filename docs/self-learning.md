# SL0–SL4 自主学习、实测与部署（3.9.0）

已实现：学习数据身份、当前模式有效配置、已结算数据冻结、增量触发、独立子进程训练、持久化恢复、只产候选接口，SL2 动作评分模型与 P1 接入，SL3 固定双模型的未来对局验收，以及 SL4 局间部署、同步和回退。候选必须先通过独立验收，才能进入自动部署；训练完成不会直接改写现役。

## SL2 动作评分

首版采用可复现的近邻模型 `observed_state_action_knn_v1`，复用现有回放训练与模型登记流程。输入为圣水、双路威胁、战场视觉、时间、卡牌与真实落点；编队意图在训练/推理两端统一置空，避免从旧策略理由推断 P1 意图。标签为已确认有效动作所在局的可信终局胜负，表示结果关联，不能解释为该落点的因果收益。它不是神经网络或自改代码系统。

同卡牌、相近状态和落点至少有 3 个独立局支持才评分；最多 8 局、每局一票，重复动作不会放大置信度。状态距离门槛为特征均方根差 0.5，落点距离门槛为归一化屏幕坐标欧氏距离 0.15。未知卡、未覆盖状态和落点不外推。WAIT 没有可靠训练标签，保持模拟评分。

训练时保存独立动作评分数组与检查报告 `manifest.action_value`。按整局留出评估，至少 8 个验证局且包含胜负，支持覆盖率至少 50%，按局平均的 Brier 误差必须优于训练集胜率常数基线。生产配置要求时间留出时，两项都须通过。失败仍保存评分头但标为禁用，不借用旧分类模型的通过状态。最终拟合使用当前策略的非冻结样本，不加入旧策略迁移样本；冻结评估局不参与拟合。通过此检查只证明观察动作的结果预测优于常数基线，不证明对局胜率上升。

`prediction.learned_action_value` 默认 `true`；仅当当前冠军已通过兼容检查、评分头检查通过、模型实际加载且影响系数大于零时参与。置 `false` 完全关闭评分及其预算预留。旧模型缺少评分头时继续原推演；学习代码指纹变化导致不兼容的权重不会被强行加载。候选生成、冠军身份、评分头通过、运行加载和实战验收是不同状态。

P1 对已完成模拟的候选作小幅评分修正，绝对值上限为 1 个模拟分，通常由现役影响系数进一步缩小。守塔损失和费用优先约束仍先于学习分；全落点空间搜索配置保持有效。`prediction.learning_budget_ms` 默认 8 毫秒，在原总预算内预留，最多 20 毫秒且不超过总预算四分之一；若整批修正未及时完成或数据异常，撤销所有修正。单次数组运算不可抢占，超时后丢弃结果，原有过期画面检查继续执行。首版动作评分使用 CPU NumPy；其余已有 GPU 路径保持原配置。

运行状态 `prediction.plan.learning` 和 `battle_prediction` 事件记录权重版本、可用原因、评分应用、支持数量、基线动作与是否改选。`selected_for_execution` 表示已交给执行流程，并非已成功出牌；回放动作的 `learned_action_value` 保留同一信息，结合已有 `action_confirmation` 判断最终确认。观察模式可计算学习分，但不执行 P1 选择。日志显示学习原因和改选标记。

SL2 验证软件链路与受控样例，不生成或激活生产冠军。SL3 在以下独立流程中实测候选。

## 日常使用

### SL4 自动部署、观察与回退

默认开启 `self_learning_deployment.enabled`。只在用户主动运行的 P1 离线对局流程中、已确认大厅时切换权重；软件更新本身不启动游戏，也不生成“实战通过”结果。指定训练机重新读取原始 SL3 账本，核对完整样本、唯一对局、预定分组、证据哈希和统计判定，同时要求现役锚点与当时一致、代码/配置/知识/辅助模型身份未变。旧代码下的提案不会自动冒充当前版本验收。

先加载候选并验证真实文件哈希、兼容性、数组和启用状态，再把新冠军、递增部署代次、旧稳定锚点和观察协议一起原子写入 `models/replay_policy/registry.json`。随后核对运行对象的加载哈希，重新取图并再次确认离线大厅。注册表写入后中断，恢复时按该代次重新加载；不重复晋级。部分文件、加载失败、运行身份变化或损坏的权重会拒绝部署或触发回退。

默认部署观察 20 局，至少 10 局后检查健康：未知结果率 ≤10%，未确认动作率 ≤15%，相对基线确认率下降 ≤5 个百分点，回退比例 ≤10%，最大计划耗时 ≤2500 毫秒，学习评分参与率 ≥1%；平均胜平负效用不能比实测基线下降超过 0.20。阈值在本次部署开始时固定。达到预算且健康通过标为 `stable`；后续无新 SL3 试验时继续用最近 20 局滚动监测，不能把初始观察通过理解成永久保证。

缺失或冲突的结算证据、运行异常、护栏失败先标为 `rollback_pending`，在下一局间恢复旧锚点，并产生更高代次的 `rolled_back` 记录。对局中不热切换。若旧锚点也损坏或不兼容，回退到无学习权重的 P1，并明确记录空模型，不声称已恢复旧权重。观察阶段暂停产生下一候选和新试验；稳定后恢复自主学习。暂停自主学习会阻止新部署，但保留当前现役的健康监测和必要回退。

私有同步有两个独立通道：原候选通道继续按配置上传未验收候选；新的 `models/deployment.json` 只发布稳定部署或回退通知及所需权重。接收端先校验授权训练机、哈希、兼容身份和递增代次，只暂存通知，不在同步线程替换冠军。随后在本机已验证的离线大厅，核对策略/知识/辅助模型契约并实际加载。更高代次的回退通知可打断旧观察期；重复通知幂等，较旧代次被忽略，同代次内容冲突被拒绝。首版自动部署对象是回放决策权重；辅助模型必须匹配，不会隐式下载或切换整套感知模型。

同步沿用后台重试：断网不阻断当前对局，只有推送成功且远端提交核验一致才登记 `deployment_publication.uploaded=true`。尚在观察的模型可以作为候选上传，但不发布稳定部署通知。Release 发布失败也会重试；已存在 Release 缺少对应资产时补传。禁用私有同步时权重仅在本机部署，不能称为已经上传。

训练、接收和部署共享模型注册表写锁，避免两个来源互相覆盖。部署状态与运行对象分开：`probation`、`stable`、`rollback_pending`、`rolled_back`，另记录加载哈希和发布状态。控制台“自主学习状态”、`self-learn status` 和运行状态文件都能查看。原始 SL3 提案中的 `deployed=false` 不会被改写；实际消费结果和代次保存在注册表的 `deployment_proposals` / `deployment`。

3.9.0 的软件测试包含真实 NPZ 加载与评分、原子提交中断恢复、观察回退、双设备通知乱序与上传失败重试。测试使用临时模型和模拟对局证据，没有部署生产权重，也没有证明新模型的真实胜率提升。

### SL3 自动实战比较

默认开启 `self_learning_trial.enabled`。用户主动启动 P1 离线对局后，指定训练机在已验证大厅检查候选。还要求 `replay.allow_bot_training` 和学习评分开启。候选的原离线检查、SL2 评分头检查、兼容身份、文件哈希及实际加载均须通过。试验期间暂缓训练；旧的同模型影响系数开关实验被 SL3 双模型对照取代。CLI 单轮学习不会自行启动对局或实测。

基线是本次已加载现役权重，挑战者是独立加载的候选权重，试测加载不写入冠军注册表。若当前没有可用权重，以无学习权重的 P1 为基线，记录中基线模型身份为空；不能称为“两份已验证冠军”。运行配置、代码、知识/卡库、其他已加载学习组件身份与两份回放权重均固定；重启后不一致、外部冠军变化或文件损坏，终止当前试验。

每个对照由两批构成，默认每批 5 局；每对批次的先后顺序在试验创建时随机确定并持久化，两侧局数相等。默认每侧 1000 局，共 200 个配对批次。每侧至少 10 局后检查健康：未知结果率不超过 10%，未确认动作率不超过 15%，确认率相对基线下降不超过 5 个百分点，回退比例不超过 10%，最大计划耗时不超过 2500 毫秒，候选至少在 1% 的决策中实际参与学习评分。零动作、零决策或关键运行证据缺失不能通过。这里只覆盖现有运行证据，不声称完成全部罕见场景或多设备实战验证。

只在完整固定预算结束时检查收益，不因途中领先提前通过。胜/平/负效用为 1/0.5/0；未知结果作对候选不利的处理（基线按 1、候选按 0），不能靠丢弃失败结算获利。按配对批次平均效用差计算单侧 Hoeffding 下界，只有下界大于默认 0.03 才为 `battle_pass`。该界允许同批局间相关，但依赖不同配对批次独立的假设；对手分布长期变化仍可能使解释受限，不是无条件胜率保证。

同一账本第 j 个候选使用不超过 `0.05 / (j*(j+1))` 的显著性预算，累计不超过首次配置的总预算；失败或中断不会重置编号。这个首版判定偏保守：耗尽预算而证据不足就是 `inconclusive`，继续使用原现役。调大预算必须在新试验开始前完成；运行中修改协议会终止旧试验。软件不会自行降低收益或健康门槛。

局间先持久化分组，再切换内存权重，并丢弃旧画面重新验证大厅；对局中不换模型。暂停自主学习后恢复原现役，已准备但未开始的分组保留；恢复不启动游戏。进程中断后，若回放已写入完整结算，按试验 ID 和序号恢复且不重复计数；已经开始却无唯一完整结算证据的试验标为 `interrupted`，不悄悄补打一局替代。单机锁阻止两个实测进程或训练任务同时改动试验。

试验回放标记 `sl3_evaluation_only`，即使旧训练许可为真，也不会进入后续训练或自主快照；它是本候选创建后的未来评估证据。原有离线门槛仅用于准入，最终收益比较来自这批共同协议下的未来实测，而非两份模型各自历史分数。长期评估集轮换和独立缺陷场景库扩充仍需后续完善。

账本在 `training/self_learning/trials/ledger.json`，通过后写入该目录下 `proposals/` 的独立待部署记录，包含两侧模型、协议、报告和证据哈希。写入中断可从已持久化判定重建。SL3 状态区分 `battle_trial`、`battle_pass`、`rejected`、`inconclusive`、`interrupted`；SL3 原始提案保持 `deployed=false` 作为不可变输入，实际部署结果以 SL4 注册表为准。提案和数据不进入代码仓库。

“工具 → 自主学习状态”、`self-learn status` 和运行状态文件可查看进度。SL3 软件回归及合成对照不代表候选已通过真实实战。通过记录由以下 SL4 流程消费。

在指定训练机启动离线训练即可；默认开启 `self_learning.enabled`。首个已验证离线大厅检查一次，随后每 20 个可信完成局检查。训练期间暂不开新局，完成后丢弃旧画面、重新验证离线入口。采集机继续采集与私有同步，不争抢训练角色。没有启动对局时，可手动运行单轮；它不会启动模拟器：

```powershell
.venv\Scripts\python.exe -m crbot self-learn status
.venv\Scripts\python.exe -m crbot self-learn cycle
.venv\Scripts\python.exe -m crbot self-learn pause
.venv\Scripts\python.exe -m crbot self-learn resume
```

`status` 只读。`pause` 持久暂停自主学习，正在运行的子进程会由监督器中止；对局本身继续。`resume` 只恢复学习许可，不启动游戏；下次审计边界继续。控制台“安全停止”停止对局及当前学习子进程，下次用户主动启动后可恢复未完成快照。中断恢复是重新运行同一任务/快照，不是恢复每一步训练计算。

“工具 → 自主学习状态”和日志显示阶段、学习目标、新增数量、门槛、候选版本及失败原因。`candidate_ready` 表示已产出候选；需结合 `quality_passed` 和 `rejection_reasons` 查看现有离线检查结果，不代表实战通过或已加载。

## 数据与训练身份

GUI、CLI 的学习审计/训练使用所选策略和决策引擎的有效配置。P1 使用 `predictive_calibrated_v2`，不会按基础配置误训 `adaptive_counterpush_v5_m3_c3`。旧策略保存键保持不变。

学习身份包含 replay/策略/预测配置、卡库哈希和代码内容身份；任务另包含数据内容、父模型和随机种子。增量按同身份的内容指纹计算，不以所有历史版本的最大动作数作为门槛。复制同一可靠对局不增加可用内容；未经确认动作、未知结果仍由现有生产过滤规则处理。

快照只复制有完成局记录的回放及对应动作，排除活动局/未写完行；校验动作数与结果一致性。保存标签来源：可信终局、确认动作，短期反馈仍为代理信号。原始图像与模型不复制进快照。训练前验证快照哈希，训练不重新读取增长中的运行目录。

数据、状态与诊断位于已被忽略的 `training/self_learning/`，模型沿用 `models/replay_policy/`。训练使用冻结快照与卡库，现有留出/冻结划分保留。本阶段不使用冻结评估数据作自动实战晋级。

## 调度与预算

默认新增门槛为 100 个可用局、500 条有效动作，还需通过生产学习审计；冷却 7200 秒。每轮使用一个现有回放学习配方（内部继续原有有限信号选择），不是无限搜索。单轮子进程墙钟上限 7200 秒，包含审计与训练；这是运行时间限制，不是显卡功耗计量。

中断最多尝试 2 次；明确训练失败的同快照不反复重训，等待新数据。锁占用延期，不消耗训练尝试次数。已登记候选但尚未写完任务状态时，恢复会识别任务 ID 并复用候选。失败、停止、容量不足均保留冠军。

每个快照上限 512 MB；完成后保留最近 2 个完成/失败任务快照，任务摘要保留。任务按单训练机锁串行运行。可在 config.json 的 `self_learning` 中调整门槛、间隔和预算；不因此放宽模型质量验收条件。

## 训练 API 与部署边界

`train_replay_policy(..., candidate_only=True, snapshot_root=..., learning_manifest=...)` 明确禁止晋级，且跳过训练装饰器的前后同步；指定训练机权限和训练锁仍执行。原手动 `replay train` 接口保留既有行为；GUI“无标注自学”的回放训练分支使用只产候选模式，示范学习分支沿用原流程。

已有后台同步仍可按配置发布/接收这些未晋级候选，但 `promoted=false` 不会触发现役替换。模型兼容指纹随真实学习代码变更重新计算；显示阶段不伪造旧模型兼容性。代码包版本、能力阶段和训练权重身份分别显示。

发布该阶段时应验证：候选不能替换冠军、重复数据不重训、快照不可变、P1 身份正确、断点恢复幂等、训练角色/锁、预算与停止，以及最小控制台窗口内当前阶段可见。通过软件回归不等于候选获得实战收益。
