# G1 方格战场推演（3.10.0）

截图经已有感知、单位跟踪和塔血条观测，形成带时间戳的战场快照；P1 将同一快照实例化为可复制的战斗状态，在各出牌分支里进行移动、选目标、攻击、法术和组合推演。UI 展示该状态的方块表示，不是另起一套与决策脱节的演示。

## 使用

更新并重启，在 P1 离线训练时点击主界面预览栏的 **方格战场**。窗口左边显示产生该数据的截图，右边显示模型战场；点击方块查看兵种、敌我、置信度、血量、空地属性、攻击层、伤害、射程、速度、碰撞半径、当前预测目标及路线。蓝色代表我方，红色代表敌方，↑ 表示空中单位，? 表示身份或血量存在估计。3.12.5 起，血量未知只保留问号，不画估计的绿色满血条；已确认摧毁的公主塔用叉号标记，退出可攻击目标和战斗模拟，本局不复活。识别到等级 11 时显示 L11。黄圈表示本帧选择的出牌位置。窗口只读，不会自行开始游戏或执行动作。停止后保留最后一帧供查看。

配置 `prediction.grid_world=true` 默认启用方格寻路与检查数据；关闭后保留原移动规则作为回退。`king_towers=true` 在生产配置中开启两个国王塔。国王塔默认按地图中央后排估计位置，可以用 `king_tower_points` 指定两个归一化锚点（我方、敌方）；未标定的位置不代表像素级精度。塔血条 `tower_bar_rois` 可保留四座公主塔，也可扩为六座，最后两项依次为我方、敌方国王塔。没有可读血条时保持血量未知，模拟使用明确标记的健康假设，详情中的 `simulated_hp` 与观测比例分开。公主塔连续废墟证据确认的零血量跨帧保持，局间重置；实时视图逐帧观测血条和废墟，不等待下一次推演。

## 地图与战斗

- 地图为 18×32 格，单位仍保留格内小数位置。第 15、16 行为河道，桥梁位置沿用当前场地标定。
- 地面路线使用有界 A*，禁止河道非桥区域和穿越建筑阻挡；同半场直通区域走直线。路线按格点、目标和障碍签名缓存，供主进程与各模拟工作进程复用。
- 空中单位不受地面河道和建筑阻挡。部队局部避让采用软减速，是简化近似，不等同于游戏中的质量、挤压和推开机制。
- 目标选择和路径选择分开，检查可攻击层、只攻击建筑属性、视野和射程。视图与模拟使用相同目标选择函数。
- 两个国王塔具有独立属性；受伤或同侧公主塔减少时按模型激活。未知实际激活状态仍是估计，特殊塔兵、进化和未支持机制不会因方块化而自动变得精确。
- 每个模拟分支复制实体、圣水、延迟弹道和效果事件。渲染不修改分支，也不向模拟器反写观测。国王塔和建筑消失会改变后续通行障碍。

## 跟踪与校正

跟踪使用预测位置关联、敌我约束及一对一占用。未知单位识别为具体兵种后尽量延续同一轨迹 ID；短暂出现泛化检测时保留最近身份，超过 2 秒未重新确认则退回未知。明确不同的已知兵种不互相匹配。一帧内多个相近单位仍保留不同 ID。

遮挡不立即视为死亡。轨迹最多保留 3 秒，超过 1.5 秒未观测的轨迹不继续作为确定可模拟实体；短时遮挡位置最多外推 0.75 秒。血量继续沿用已有新鲜度规则。确切兵种未知的我方单位可显示为方块，但没有虚构战斗属性；敌方未知身份仍采用标明的多种假设。

`plan.grid_world` 记录单位数据、地图、目标、路径、出牌位置和下一观测校验。连续两次新鲜观测才比较同一轨迹：记录按路线和速度外推的位置误差、可信血量比例变化。每次新截图重新校正战场，而不是长期相信旧模拟。位置比较是“未计未来交战的移动预测”，血量变化是观测差值，不能解释为战斗伤害模型已验证或已经完成参数学习。此阶段不自动改写卡库、识别权重或冠军模型。

## 验证与边界

回归覆盖地面过桥、空中通行、建筑绕行、分支隔离、攻击目标层、身份升级不重复、近距离多单位、遮挡过期、国王塔激活、同一轨迹下一帧误差，以及串行/并行结果一致性；检查窗口在最小尺寸下可操作。

模型完整性受截图识别质量制约：未识别单位、遮挡、护盾和缺少标定的国王塔不能凭地图恢复真实信息。法术与弹道沿用当前模拟事件，尚未被观测确认的敌方法术不会被假装成已知事件。方格化不保证全局最优、零漏防或胜率提升。日志、截图与检查报告继续留在被忽略的本地目录，不进入代码仓库。
