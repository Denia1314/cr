# YOLO 连续识别（3.15.3）

旧的 YOLO 预览跟随机器人决策循环更新；截图约 30 FPS，但一次推演结束前不会再次调用识别，因此实测更新可能不到 1 FPS。现在引擎启动独立的 `YoloStream`，持续使用最新截图，默认目标 20 FPS。队列容量为 1，跳过积压截图；只有真实模型推理成功的结果计入识别次数。停止机器人时关闭线程。模型预热和加载阶段不算稳定速度。

识别线程独占一套模型及观察状态，不修改正在推演的策略模型。它输出当前截图上的类别、框、置信度和等级标记阵营证据，并保留有证据时的公开模型回退。血条读取继续在决策路径进行，不阻塞逐帧 YOLO 展示。提高识别频率不等于每秒执行 10 次决策或出牌；原有决策、手牌、费用、动作确认、离线安全门及发牌前复核保持。

提速包括：只扫描原来允许的战场等级标记区域，用等价整数/图像运算替代 RGB 浮点反复归约；主/备用模型复用同帧等级标记；缺少任何阵营标记时不重复运行必定无法接受单位的备用模型；公开模型的 FP16 像素归一化使用逐字节精确查表。未降低置信度、输入分辨率或更换模型权重，模型的本地准确率及对局验收状态也不因 FPS 改变。

“YOLO识别”和“同帧对照”优先显示连续识别线程的同帧截图与结果，显示“识别 FPS / 单帧 ms / 更新 FPS”。识别 FPS 是实际成功结果在近 5 秒内的吞吐量；更新 FPS 是界面接收新结果的频率。结果超过 0.5 秒未更新或后台报错时，停止将旧结果作为实时数据展示。`.training-sync/runtime-status.json` 的 `yolo_stream` 记录实际速率、耗时、捕获帧年龄、跳帧数量及错误；`battlefield_recognition` 仍是原决策路径的模型状态，两者不要混读。

可用 `automation.continuous_yolo=false` 关闭独立识别，默认开启；`automation.yolo_target_fps` 默认 20，目标范围 10–60。模型线程额外占用一套识别模型的内存/显存，实际吞吐量受硬件、画面内容、备用模型和同时运行的任务影响，目标配置值不代表已达到。

## 只读速度验收

在模拟器已运行且显示游戏画面时，用共享 Python 执行 `tools/benchmark_yolo.py`。工具只读截图，不点击、不主动启动新对局；模型预热后默认测量四个连续 5 秒窗口，每个窗口至少 10 FPS 才返回成功。包含真实主模型及需要时的备用模型推理、类别与阵营处理，不把重绘次数当作识别次数。报告保存在 `reports/yolo-speed/acceptance.json`，不提交原始截图、模型或本地报告到代码仓库。

```powershell
& "$env:LOCALAPPDATA\RoyalLab\python-envs\python-3.12\Scripts\python.exe" tools\benchmark_yolo.py
```

重新启动机器人后才启用新识别线程。实时截图速度验收、实景回放双模型压力测试和真实对局准确率/收益验收是不同证据；空场景速度不能单独证明复杂对局的速度或准确率。
