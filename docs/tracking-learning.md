# 跟随关联训练（3.22.1 / V9，实验版）

V9 接通数据、人工身份确认、训练、独立验证和可选运行时加载。它训练“两个身体观测是否属于同一个单位”的关联评分，YOLO 仍负责找到身体和识别兵种。首版是基于颜色直方图、距离、框重叠、面积变化、兵种类别及时间间隔的监督分类器，并非训练新的 YOLO 网络或深度外观编码器。同类单位外观相同、严重遮挡、姿态变化仍可能使关联不明确。

## 使用步骤

1. 重启机器人后，当前配置在局内每秒采集 2 帧，每局最多 600 帧，写入 `training/tracking-capture`。后台队列容量为 2；写盘跟不上会丢弃样本，不等待写盘完成再识别。源截图、实际帧时间与检测建议一起保存，建议从不自动成为正确身份标签。采集状态可查看 YOLO 流的 `tracking_capture.saved/dropped/error`。
2. 双击项目根目录的 `prepare_tracking.bat`。优先使用最近三场连续采集，各选一个最多 40 帧的小片段；不足三场时补充已有历史截图。历史截图可能较稀疏，不等于连续视频。
3. 在页面拖框标注兵种身体，填写英文兵种 ID、阵营和持久单位编号。同一场内，同一个身体持续使用同一编号；新下出的同类单位必须新编号。未知或遮挡到无法判断的帧不要勾选确认。错误框可用同一编号重画替换，或清空本帧重画。
4. 每帧人工核对后勾选确认，保存 `tracking-annotations.jsonl`。页面支持重新加载保存的标注继续编辑。训练需要三组完整确认的数据，不能直接把空模板送去训练。
5. 把保存的标注文件拖到 `train_tracking.bat`。候选写入 `models/tracking/candidate-随机编号.json`；训练与评估结果保存在候选中。命令行默认输出 `models/tracking/candidate.json`，已有文件会拒绝覆盖。

标注路径是本机原图的绝对路径，跨电脑迁移需随原图一起处理并修正路径。原图、采集、人工标签、候选权重均留在忽略目录；本次没有把它们提交公开代码仓库或发布私有候选。

## 数据与验收门槛

按整场对局分开训练、验证和测试。拒绝同一对局跨组、相同图片跨组、重复/倒退时间、非法身体框、同一编号改变兵种或阵营、未人工确认的帧。时间差超过 3 秒的相邻截图不生成训练对；只使用邻近身体作为关联对照。

每组至少需要 20 个同一单位正例、20 个不同单位负例，其中至少 10 个必须是同兵种不同单位的负例。训练仅使用训练组更新参数，验证组选择参数，独立测试组只作最终评估。候选在验证和测试的关联精确率均至少 98%、召回率均至少 50% 才具备加载资格。这些是身体配对指标，不是完整轨迹 IDF1/HOTA，也不代表对局准确率或胜率。

## 运行时加载

通过上述离线门槛的候选也不会自动部署。在 `prediction.tracking_association_model` 配置候选路径后重启，加载器再次检查结构、有限参数、样本门槛和指标；失败记录错误并保留 V8 原关联。

有模型且有同帧图像时，敌方跟踪器提取身体外观并用学习评分做双向唯一关联。最低匹配概率 0.90，与第二候选差至少 0.10，并仍遵守移动范围、80% 初始身份锚点、阵营和超时约束。模型已加载但有分数的关联未通过时拒绝绑定；没有外观数据时保留原几何关联。推演审计中的 `compute.tracking_association.loaded/error/battle_accepted` 区分实际加载与实战验收。

当前默认未配置关联模型路径。当前交付只有链路和合成回归训练验证，真实人工身份标签尚未齐备；没有声称真实模型已训练完成、已加载或完成对局验收。
