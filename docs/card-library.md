# 卡牌与切片库（3.15.6 / UI3）

双击 `start_ui.bat`，点击工作台右上角的 **卡牌库**。已有窗口需要关闭后重新打开。此入口使用 Tk 与已有 Pillow，不启动浏览器、不加载 YOLO 权重、不触发训练。

## 浏览

卡牌按行排列，每张显示图标、名称、费用和关联切片数量。每页最多加载 24 张缩略图；可滚动、翻页，按中文名、英文名、卡牌 ID 或切片类别搜索。原始数据未提供中文名时显示英文名。

点击卡牌后显示切片网格，可按类别、GitHub / 本地来源、原始阵营编号 0 / 1 筛选。类别列表有圆角、淡入淡出、展开收起及滚动，卡牌和切片都有悬浮渐变；遵循已有 `CRBOT_REDUCED_MOTION=1` 设置。点击切片可看透明背景预览、尺寸、文件名、对应卡牌，并打开文件位置。卡牌资料显示下载的基础属性及各等级数值。

初次接入时本机有 132 张已有卡牌，其中网站目录 121 张；GitHub 导入库含 154 个素材类别、4,525 张带阵营切片及 129 张场景素材。实际数量从当前文件读取，不硬编码。没有下载切片时仍能浏览卡牌、添加本地切片，顶部会提示导入库缺失。

## 对应关系

- 网站记录按规范化后的卡牌 ID 对应 `data/cards.json`；网站原始记录、来源和各等级属性保留。
- YOLO 类别先使用确切类别名与明确别名关联：如 `archer` 对应 `archers`，`zappy` 对应 `zappies`。
- 普通、进化、拆分形态保留各自类别。骑士下有 `knight` 和 `knight-evolution`；石头人下有 `golem` 和 `golemite`；凤凰、圣水戈仑及小王子的伴生单位分别归组，不把它们的战斗数值合并。
- 共用单位按多对多关系展示，如骷髅同时关联骷髅兵、骷髅军团、墓园、女巫等；哥布林团关联近战与投矛哥布林；三个火枪手关联火枪手。共享普通单位不自动推断对应卡牌拥有进化形态。
- 血条、国王塔、背景、未知类别等进入 **未对应 / 场景素材**；没有素材的卡牌显示 0 张，不借用相似名字的素材。**编辑对应关系** 可搜索卡牌、多选或清空关联，保存后重新打开仍保留。列表关联只是素材管理，不改变实时识别的类别适配或单位战斗统计。
- `0 / 1` 是源数据的阵营编号，保留原值；实时画面仍按等级标记识别阵营。

## 添加

**添加卡牌**：填写唯一 ID（小写字母、数字、下划线）、中文或英文名、费用、类型、稀有度，选择本地图标。保存到配置中 `dataset.card_catalog` 指定的实际卡牌文件；未知字段与其他卡牌保留，保存前备份到 `training/card-library/backups/`。图标复制到本地素材目录，卡牌文件引用其相对路径。添加卡牌定义后，战斗属性、召唤物知识和模型识别支持仍需单独补齐，不会自动变成已验收可出牌的新卡。

**添加切片**：打开目标卡牌，选择已有类别或填写新类别，选择来源阵营编号，再多选透明 PNG。检查整个批次后保存，拒绝无透明通道和完全透明的图片，同类别、阵营和内容重复的切片会跳过。向已有共享类别添加时保留所有已有卡牌关联。

新增切片与关联保存在 `training/card-library/manifest.json` 和 `training/card-library/sprites/`。GitHub 原始库 `training/external/katacr-slices/` 与网站下载快照不被覆盖。新卡图标、切片、备份及导出数据均位于已有忽略的 `training/`，不作为代码上传 GitHub；需要转移新卡时须同时保存卡牌文件与本地素材目录。

## 导出用于后续训练

点击 **导出切片库**，选择一个尚不存在的输出目录。导出在后台执行，对所有素材核对哈希，复制成独立目录，保存原类别、来源、阵营、卡牌关联与上游版本，附带原数据集许可证。不会覆盖已存在目录或自动启动训练、切换模型。

例如导出到 `training/exports/card-library-slices` 后，可以使用现有切片导出工具制作合成训练数据：

```powershell
python -m crbot.slice_dataset export --source training/exports/card-library-slices --output training/exports/card-library-bootstrap
```

此处 `python` 指项目环境的 Python。合成数据仍是启动训练素材，不能充当真实对局验收。新类别是否能用于机器人实时识别还取决于类别适配、训练及验收；导出文件的 `promoted` 和 `battle_acceptance` 保持 false。真实战场导出只利用切片库类别表，新增图片通过合成导出进入训练；真实标注仍须另行补充。参见 [YOLO 切片训练说明](yolo-slices.md)。

## 验证

相关测试覆盖确定别名、进化、共享单位和伴生形态、关联持久化、卡牌文件备份与兼容加载、批量校验与去重、独立导出与损坏拒绝、路径边界、入口复用、实际 Tk 点击与筛选、长列表滚动及最低窗口布局。UI3 表示管理入口已实现，不表示模型已训练或对局已通过验收。
