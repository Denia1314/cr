# 两台电脑与团队共享自动对战经验

代码仓库：`Denia1314/cr`。私有数据仓库：`Denia1314/cr-training-data`。

当前版本共享自动对战回放中的状态、动作、胜负、策略版本和已提取的画面特征，以及通过验证的回放策略模型。人工示范、精确识别训练用截图、标注和检测器模型仍保存在各自电脑，不在这一版的共享范围内。

## 新成员 / 第二台电脑

1. 仓库所有者分别邀请成员加入代码仓库和数据仓库，数据仓库需要 **Write** 权限。成员用自己的 GitHub 账号接受两个邀请，不共用密码或 Token。
2. 安装 Git、Python 3.10 或更新版本、GitHub CLI。GitHub CLI 可以用 `winget install --id GitHub.cli -e` 安装。
3. 使用自己的账号运行 `gh auth login`。在已能访问私有仓库的环境克隆 `Denia1314/cr`；如果 Git 尚未使用该登录，可先运行 `gh auth setup-git`，再执行：

   ```powershell
   git clone https://github.com/Denia1314/cr.git
   cd cr
   python -m pip install -r requirements.txt
   ```

4. 双击 `setup_sync.bat`。默认连接 `Denia1314/cr-training-data`，生成本机独立编号，并配置为**采集机**。不要加 `--trainer`。
5. 重启 `启动控制台.vbs`。控制台打开时每 60 秒后台同步一次；也可以点击左侧“双机数据同步”，或双击 `sync_data.bat` 立即同步。
6. 在这台电脑完成 MuMu 连接和离线画面标定，然后正常运行机器人。配置中的策略版本和卡牌知识库应与训练机一致。

只有代码仓库权限时，配置会提示无法访问数据仓库。请确认邀请已经接受，且 `gh auth status` 显示的是受邀账号。

## 训练与模型

当前初始化的电脑是唯一回放训练机。成员电脑上传对局，也下载其他成员的经验；点击“无标注自学”可以查看累计数据，但不会启动共享回放训练。

训练机仍通过“无标注自学”或以下命令触发训练；同步本身不会不断重训：

```powershell
python -m crbot replay train
```

训练开始前会尝试同步，断网可使用上一次同步后的本地数据。数据量或验证指标不达标时不会发布模型。通过验证的候选在训练后或下一次后台同步时上传；接收端检查模型 SHA-256，以及训练参数、卡牌目录和相关代码的一致性。

默认 `replay.allow_bot_training=false` 保持不变：共享合格的影子候选不代表启用实战。只有训练机发布了已晋升模型且接收端也显式启用该配置，才会更新接收端冠军模型。模型在下一次开始运行机器人时加载，不在一局中途替换。

## 同步行为

- 结算记录必须已完整写入，动作数量与结算声明一致，才会导出；正在写入的最后一行和未结算对局等待下一次同步。
- 每局一个不可变文件，按设备 UUID、运行 UUID 和对局编号区分。同名文件夹与同秒开始的记录不会混在一起。
- 导入使用临时目录后整体替换，训练程序不会读到半份导入数据。重复同步不会新增样本，已导入记录不会再次上传。
- 两台电脑同时上传时自动拉取、重放本机新增提交并重试；不会使用强制推送。上传失败的数据留在本地，下次补传。
- 已发布对局如果后来被手动改写，会报告冲突并保留双方原始数据，不能用同步覆盖历史记录。
- 正常自动同步发生在控制台打开期间；直接关闭程序后最后尚未上传的记录会在下次打开时补传。关机前可手动同步一次。
- 后台同步与主游戏线程分开；网络错误记录在控制台和本机状态文件，不会停止游戏采集。

本机设置、设备编号、Git 缓存和同步状态在 `.training-sync/`，被代码仓库忽略。**不要把这个目录复制给另一台电脑**；每台电脑运行一次配置脚本。重复配置会保留本机编号和已有训练机角色。`--trainer` 只用于第一台训练机的初始化，不能把训练机编号换成另一台的编号。

查看本机角色和最近结果：

```powershell
python -m crbot sync status
```

同步使用系统 HTTPS 代理（若已设置）以及 GitHub CLI 的凭据，不写入或上传密码和 Token。单局记录上限 10 MiB，单模型上限 50 MiB；共享工作文件超过 512 MiB 时暂停新上传并提示迁移存储。Git 历史另占空间，应定期关注数据仓库大小；本方案适合当前小规模结构化回放，不用于无限存放图片。
