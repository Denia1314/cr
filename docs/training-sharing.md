# 两台电脑与团队共享自动对战经验

代码仓库：`Denia1314/cr`。私有数据仓库：`Denia1314/cr-training-data`。

当前版本共享自动对战回放中的状态、动作、胜负、策略版本和已提取的画面特征，以及通过验证的回放策略模型。人工示范、精确识别训练用截图、标注和检测器模型仍保存在各自电脑，不在这一版的共享范围内。

## 新成员 / 第二台电脑

1. 仓库所有者分别邀请成员加入代码仓库和数据仓库，数据仓库需要 **Write** 权限。成员用自己的 GitHub 账号接受两个邀请，不共用密码或 Token。
2. 安装 Git、Python 3.10 或更新版本、GitHub CLI。GitHub CLI 可以用 `winget install --id GitHub.cli -e` 安装。
3. 使用自己的账号运行 `gh auth login`。在已能访问私有仓库的环境克隆 `Denia1314/cr`；如果 Git 尚未使用该登录，可先运行 `gh auth setup-git`，再执行：

   ```powershell
   git clone https://github.com/Denia1314/cr.git
   cd cr
   ```

4. 双击 `setup_sync.bat`。脚本会先检查并自动安装 Python 依赖，再连接 `Denia1314/cr-training-data`、生成本机独立编号，并配置为**采集机**。不要加 `--trainer`。
5. 重启 `启动控制台.vbs`。控制台打开时每 60 秒后台同步一次；也可以点击左侧“双机数据同步”，或双击 `sync_data.bat` 立即同步。
6. 在这台电脑完成 MuMu 连接和离线画面标定，然后正常运行机器人。配置中的策略版本和卡牌知识库应与训练机一致。

只有代码仓库权限时，配置会提示无法访问数据仓库。请确认邀请已经接受，且 `gh auth status` 显示的是受邀账号。

## 训练与模型

当前初始化的电脑是唯一回放训练机。成员电脑上传对局，也下载其他成员的经验；点击“无标注自学”可以查看累计数据，但不会启动共享回放训练。

训练机仍通过“无标注自学”或以下命令触发训练；同步本身不会不断重训：

```powershell
python -m crbot replay train
```

训练开始前会尝试同步，断网可使用上一次同步后的本地数据。数据量或验证指标不达标时不会发布模型。通过验证的候选在训练后或下一次后台同步时上传；接收端检查模型 SHA-256，以及训练参数、卡牌目录和相关代码的一致性。

### M1：出牌确认与统一评估

机器人现在为每次出牌分配唯一 `action_id`，并记录 `proposed`、`sent`、`confirmed`、`rejected` 或 `unknown` 状态。点击后会在有界时间内观察连续画面，至少同时满足两项独立证据（稳定手牌替换、圣水扣减、卡槽视觉变化）才确认成功。拒绝和未知会回滚策略的费用、阵型和支援计数；未知只设置短暂保护，不自动重复点击。回放保留完整尝试，但 `replay.require_action_confirmation=true` 时只有 `confirmed` 动作进入新模型训练，旧记录保持 `legacy_unknown`，不会被补写成已确认。

审计会同时显示原始对局/动作、可信结算、去重后的可用动作、确认状态和排除原因。选牌排序新增 `relative_random_v1` 指标，以当前候选手牌数量的随机前二/后二期望为基线；两张牌的命中不再单独带来排序提升。训练会按完整对局建立确定性的训练、验证和冻结评估集，并在候选清单中保存对局 ID 与 SHA-256 指纹。

只读评估不会改写冠军、注册候选、同步或上传模型：

```powershell
python -m crbot replay evaluate
python tools/evaluate_replay_transfer.py --evaluate
```

### 上一代经验用于当前模型

当前 `training_policy_version` 仍是 `adaptive_counterpush_v5`，其数据量门槛、随机整局验证和最新时间窗验证都只统计 V5。`transfer_policy_versions` 显式允许 `formation_counterpush_v4` 作为辅助选牌经验；来源版本原样保留，不把旧记录改标为 V5。

训练读取时会按完整对局动作内容和原始时间戳去重，避免另一台电脑复制历史运行目录、重新上传后导致同一局同时进入训练和验证。至少两条动作完全一致且时间戳有效才合并；单动作或缺少有效时间戳的记录不自动合并。原始文件保留。

历史 V4/V5 记录没有新的确认字段时只作为 `legacy_unknown` 审计，不会被伪造为 `confirmed`；在生产配置的确认门槛打开期间，它们不会进入当前版本的新训练，需先采集带确认状态的新对局。

旧版每条选牌样本权重为 `transfer_sample_weight=0.25`，且旧版总权重上限是当前版本总权重的一半。落点学习仅使用 V5 胜局；时间窗验证还会排除在验证窗口开始后才结束的旧版对局。每次训练都在完全相同的 V5 验证对局上重训“仅 V5”对照，迁移候选须满足原有质量门槛、随机验证综合分提升至少 `minimum_transfer_score_gain=0.01`，且时间窗综合分不退步，才会进入冠军比较。对局胜负是弱监督信号，不代表胜局的每一步都是正确操作。

```powershell
python tools/evaluate_replay_transfer.py --train
```

此命令检查共享记录一致性，保存 `reports/*_replay_transfer.json`，并按正常门槛注册本地候选。未晋升时继续保留现有冠军；模型发布仍由训练机的既有私有同步流程完成。

### 短期动作效果学习

新增 `local_feedback_weight=0.15`，在整局胜负学习之外增加短期效果预测。原始胜负标签保持不变，后续画面只生成训练目标，不进入出牌前的输入特征。新数据每约 0.6 秒保存一次紧凑局势观察，最多记录出牌后 8 秒、12 帧，并在下一张己方牌出手前截断；不额外存截图。

- 防守：比较同一路敌方威胁与推进距离。连续多帧威胁减轻给出低置信正信号；威胁加重或敌方继续接近给负信号。旧回放只有下一次出牌前状态时，置信权重仅 0.2。
- 不确定情况：观察太早、太晚、靠近己方塔、单帧敌人消失、缺字段或混入下一张牌后的观察，均跳过。
- 进攻/反攻：仅当已验证的战场检测器支持 `ally__` 类并实际观察到己方单位位置时，使用连续位置变化生成推进信号。没有检测器时记为未知，不以编队记忆代替真实存活，也不把威胁消失当作打掉塔血。仅有防守反馈的模型不会用这些样本预测进攻效果。
- 落点：启用短期反馈的候选过滤观察到明显负效应的胜局动作；允许持续正反馈的败局动作提供防守落点。它们依然只是视觉代理信号，不能视作已证明的因果收益。

验证仍按 V5 完整对局隔离，额外比较相同数据上“不使用短期反馈”的候选。随机与时间窗验证均需至少 50 条有效反馈、12 局，短期预测误差须优于零变化与训练集均值两个基线中更好的一个，且整局综合分不能退步；原有晋升门槛仍全部生效。无需手动标注。训练未晋升时，已有冠军继续工作，新采集字段供以后训练使用。

是否允许实战使用以本机 `replay.allow_bot_training` 配置为准：共享合格的影子候选不代表晋升。只有训练机发布了已晋升模型且接收端也启用该配置，才会更新接收端冠军模型。模型在下一次开始运行机器人时加载，不在一局中途替换。

## 同步行为

- 结算记录必须已完整写入，动作数量与结算声明一致，才会导出；正在写入的最后一行和未结算对局等待下一次同步。
- 每局一个不可变文件，按设备 UUID、运行 UUID 和对局编号区分。同名文件夹与同秒开始的记录不会混在一起。
- 导入使用临时目录后整体替换，训练程序不会读到半份导入数据。重复同步不会新增样本，已导入记录不会再次上传。
- 两台电脑同时上传时自动拉取、重放本机新增提交并重试；不会使用强制推送。上传失败的数据留在本地，下次补传。
- 已发布对局如果后来被手动改写，会报告冲突并保留双方原始数据，不能用同步覆盖历史记录。
- 正常自动同步发生在控制台打开期间；直接关闭程序后最后尚未上传的记录会在下次打开时补传。关机前可手动同步一次。
- 后台同步与主游戏线程分开；网络错误记录在控制台和本机状态文件，不会停止游戏采集。

本机设置、设备编号、Git 缓存和同步状态在 `.training-sync/`，被代码仓库忽略。**不要把这个目录复制给另一台电脑**；每台电脑运行一次配置脚本。重复配置会保留本机编号和已有训练机角色。`--trainer` 只用于第一台训练机的初始化，不能把训练机编号换成另一台的编号。

查看本机角色和最近结果：

```powershell
python -m crbot sync status
```

同步使用系统 HTTPS 代理（若已设置）以及 GitHub CLI 的凭据，不写入或上传密码和 Token。单局记录上限 10 MiB，单模型上限 50 MiB；共享工作文件超过 512 MiB 时暂停新上传并提示迁移存储。Git 历史另占空间，应定期关注数据仓库大小；本方案适合当前小规模结构化回放，不用于无限存放图片。
