# 实时战场刷新

此前同帧对照直接读取 `policy.grid_frame`，只有推演完成后才发布新记录。
显示线程即使以 30 FPS 调度，仍可能只有 2 FPS 的新数据。

现在默认“同帧对照”和“方格战场”读取独立的 `LiveGridStream`：

- 每张新截图运行稀疏光流，通过正反向一致性检查后更新最近识别单位的位置。
- 当前画面的敌方等级标记可立即作为身份未知的观测加入，不等待推演完成。
- 兵种身份仍来自最近的模型记录，最多沿用 2 秒；缺少有效特征、光流不一致或越界的单位移除。
- 不复制旧的预测路线、行动及单位血量到当前观测。塔的位置为固定几何锚点，血量留空。
- 该通道仅供检查界面，不能替代策略证据、出牌复核、训练标签或模型验收。

“推演快照”继续显示推演实际使用的截图和模型、路线与行动，帧率由推演产出决定。
画面和方格始终成对发布。位置跟踪帧率不等于兵种重新分类帧率，也不等于策略决策帧率。

后台绘图最多保留一个任务。完成的图像在 UI 线程上传前先启动下一帧绘图，
重叠 CPU 绘制与 Tk 显示。截图与网格分层上传，不重复上传放大模式中的大片空白边距。
绘图完成检查与 30 FPS 显示期限分开，避免刚完成的画面额外等待整个周期。
隐藏区域停止绘制，尺寸/模式改变时丢弃不匹配的旧结果。
日志每轮最多处理 32 条或 4 毫秒，剩余消息留到下一轮。窗口关闭时取消回调并停止绘制工作线程。

MuMu 采集在原生缓冲区上直接解码为独立 RGB 图像，省去多次全尺寸复制、翻转及颜色转换；
测试验证上下方向、颜色及下一次截图不会修改上一帧。

运行状态的 `live_grid` 单独报告处理帧数、实际帧率、耗时和错误。
显示目标为 30 FPS，默认采集目标为 40 FPS，给处理开销和抖动留出余量。
`vision.opencv_threads=1` 限制 OpenCV 小任务的内部并行，避免与推演、采集和 UI 争用大量线程；
这是进程级设置，不会禁用 GPU 或独立推演进程。负载及采集上限仍可能使实际帧率低于目标。
当前仓库代码更新后需重启程序；已打包的独立 EXE 需要重新构建才能包含这些修改。
